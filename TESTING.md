# Testing Chain Theorem

This guide is for a human tester. It lists what to install, every automated test command with what
it proves and what you should see, a manual play-test script with an expected result for each step,
how to reset local data, and the known limitations. Requirement IDs refer to `docs/DESIGN.md`.

> Status markers: commands marked **(M4+)** or later become meaningful when that milestone lands;
> until then they print a short "arrives in Mx" note and exit successfully. `PROGRESS.md` says which
> milestones are done.

## 1. Prerequisites

| Tool                    | Version                                                                             | Needed for                                           |
| ----------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------- |
| Node.js                 | 22 LTS (22.12 or newer) or 24 LTS                                                   | everything                                           |
| pnpm                    | 10.x (`corepack enable` picks the pinned 10.33.0)                                   | everything                                           |
| Chromium for Playwright | installed by `pnpm --filter @chain-theorem/client exec playwright install chromium` | `pnpm test:e2e`, `pnpm measure:client`               |
| PostgreSQL (optional)   | 16 or 17 server binaries, or `TEST_PG_URL`                                          | `pnpm test:db:pg` (starts a throwaway local cluster) |
| Docker (optional)       | 24+                                                                                 | `pnpm test:db:pg` when neither of the above exists   |

One-command setup:

```sh
corepack enable && pnpm install && pnpm check
```

`pnpm check` must end with `deps:check ok`. No accounts or keys are needed for anything in this
guide except the optional Paddle sandbox step.

## 4. Resetting local data

`pnpm seed` wipes the local data of `pnpm dev` (D1, R2 and Durable Object storage under
`.wrangler/state`) and creates test accounts `level1@local.test`, `level10@local.test`,
`level25@local.test` and the under-18 `minor@local.test`, each with a legal saved loadout (levels 10 and
25 own the whole catalogue). Sign in with those emails; the links print in the `pnpm dev` console. Local-only battles (M3) keep their
settings and loadouts in browser storage: clear the site data to reset them.

## 5. Known limitations and human-only items

- Balance numbers come from the AI simulator until real players exist; see
  `docs/PLAYTEST_GATE_1.md`.
- Final creature art and music are human-only; procedural art ships until then.
- Production deployment, Neon/Hyperdrive, Paddle live billing, email delivery and OAuth keys are
  human-only (see `DEPLOY.md` and `PROGRESS.md`).
